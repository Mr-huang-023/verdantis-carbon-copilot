# 绿境 · 碳智囊（Verdantis Carbon Copilot）

面向中小企业的**可审计 AI 碳盘查工具**。核心理念：**AI 负责理解与组织，计算由确定性引擎给出，每个数字都能追到出处。**

> 本项目为「全国高校 AI Web 开发挑战赛」参赛作品。页面中的企业信息、客户数量等均为演示数据，接口与因子口径在文末说明。

---

## 1. 它解决什么问题

中小企业做碳盘查的真实痛点不是不会套公式，而是：

| 痛点 | 现状 | 本项目的做法 |
|---|---|---|
| 票据格式混乱 | 电费单、燃气单、油票各不同，人工抄录易错 | 多模态模型抽取字段，缺失字段显式标记为待补，不猜测 |
| 因子版本不统一 | 网上搜到的因子来源不明，审计无法复核 | 因子库结构化存储，每条带机构、年份、适用边界，界面可展开 |
| 通用大模型会编数字 | 对话式 AI 给出的排放量无法验证 | **模型不参与算术**，所有数值由纯函数计算，冲突以计算为准 |
| 结论无留痕 | 报告只有结果，没有过程 | 计算式、因子出处、人工确认记录全部写入报告 |

## 2. 能力与边界

**已实现（可离线运行）**
- 8 类活动排放因子库，含出处与适用边界
- 前端确定性计算器：录入即算，结果可展开溯源
- 排放总量与树木固碳折算（演示口径 18 kgCO₂e/株·年）
- AI 解读面板：流式输出 + 关键词检索因子的轻量 RAG

**明确不做（避免过度承诺）**
- 不做碳配额交易、不做第三方核查认证
- 因子为演示口径，正式盘查必须替换为适用年度与地区的官方因子
- 未接入企业真实 ERP/电表数据，票据抽取目前为设计能力，需配置模型密钥后验证

## 3. 技术架构

```
浏览器
 ├─ app/workbench        活动数据录入 + 实时计算（纯前端，断网可用）
 ├─ app/products         产品说明与因子口径公开表
 └─ app/about|contact    方法与联系方式
        │  POST /api/chat（仅发送计算结果，不发送原始票据）
        ▼
Next.js Route Handler（Node 运行时）
 ├─ 限流：内存计数，10 次/分钟/IP
 ├─ 检索：searchFactors(关键词) → 命中因子 + 出处注入 system prompt
 ├─ 调用：DeepSeek Chat Completions（stream=true）
 └─ 转发：SSE → 纯文本流 → 前端逐块渲染
```

**技术栈**：Next.js App Router · TypeScript · Tailwind CSS v4 · DeepSeek API（OpenAI 兼容协议）

**为什么不用 Agent 框架**：当前链路只有「检索因子 → 组织解释」两步，引入 LangChain 等框架会增加抽象层而不增加能力；工具调用在 `src/lib` 中以纯函数实现，便于单测与审计。


## 5. 本地运行

前置：Node.js ≥ 20.9（本项目在 Node 24.22.2 验证）、npm ≥ 10。

```bash
npm install
cp .env.example .env.local      # Windows: copy .env.example .env.local
# 编辑 .env.local，填入 DEEPSEEK_API_KEY
npm run dev                     # http://localhost:3000
```

> 未配置密钥时，工作台的**计算与溯源功能完全可用**，AI 面板会提示「暂不可用」——这是有意的降级设计，保证演示不依赖网络与额度。

生产构建：

```bash
npm run build
npm start
```

## 6. 安全实践

- 密钥仅存于服务端环境变量；`.env*.local` 已加入 `.gitignore`
- 前端永远不接触模型凭证，所有模型调用经 Route Handler 转发
- 接口做入参校验（角色白名单、长度截断、消息条数上限）与限流
- 发送给模型的只有计算结果摘要，不上传原始票据图片
- 未配置密钥时 fail-closed，返回明确提示而非静默失败
